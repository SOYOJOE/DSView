# AGENTS.md — DSView

DSView is a Qt5/Qt6 C++ GUI application for DreamSourceLab instruments (logic analyzers, oscilloscopes), based on sigrok/PulseView.

## Build (Linux)

```bash
# Prerequisites (Debian/Ubuntu):
sudo apt install git gcc g++ make cmake qt5-default libglib2.0-dev zlib1g-dev \
  libusb-1.0-0-dev libboost-dev libfftw3-dev python3-dev libudev-dev pkg-config

# Build (make-based):
cmake . && make          # Output binary → build.dir/DSView

# Build (ninja-based, developer-preferred):
cmake --build cmake-build-debug-system-gcc13
```

- C++11, C99 are forced via `-std=c++11` / `-std=c99`.
- Default build type is `RelWithDebInfo`; `-O3` is added unconditionally.
- Wins: static deps; Unix: dynamic deps.
- The ninja build dir (`cmake-build-debug-system-gcc13/`) is the primary developer build; it also provides `compile_commands.json` for clangd/LSP.

## Clean

```bash
./cmake_clear           # Removes build.dir, CMakeFiles, Makefile, CMakeCache, moc_*/qrc_* artifacts
```

## Run

```bash
./run_dsview.sh          # Sets PYTHONHOME=/usr, then execs build.dir/DSView
```

Setting `PYTHONHOME` is required for Python-based protocol decoders to work.

## Project layout

| Dir | Role |
|---|---|
| `DSView/` | Qt C++ application (GUI, views, dialogs, config, UI) |
| `libsigrok4DSL/` | C driver library — USB device I/O, hardware backends, session management |
| `libsigrokdecode4DSL/` | C decoder library — binds to Python protocol decoders at runtime |
| `libsigrokdecode4DSL/decoders/` | ~150 Python protocol decoders (I2C, SPI, UART, CAN, JTAG, etc.) |
| `common/` | Shared C/C++ utilities (minizip, xlog logger) |
| `low_part/` | Embedded C for GPIO event capture (separate from main app) |
| `lang/` | Language resource files (`cn/`, `en/`) |

## Key architectural notes

- **Application entry**: `DSView/main.cpp` → `QApplication` → `AppControl::Instance()` (singleton) → `pv::MainFrame`.
- **AppControl** (`DSView/pv/appcontrol.h`) is the central singleton that initializes the sigrok context, manages sessions, and owns the device agent.
- **SigSession** (`DSView/pv/sigsession.h`) wraps a sigrok session for data capture/decoding.
- **config.h** is generated by CMake from `DSView/config.h.in` — defines `DS_TITLE`, `DS_VERSION_STRING`, etc. The generated file is committed at `DSView/config.h`.
- **Qt MOC**: all headers in `DSView_HEADERS` get moc'd. Generated files are `moc_*.cpp`.
- **Qt RCC**: resource files (`DSView.qrc`, `breeze.qrc`, `language.qrc`) are compiled to `qrc_*.cpp`.
- **64-bit only**: runtime check in `main.cpp` refuses to run if `sizeof(u64_t) != 8`.

### UART_VCD driver (libsigrok4DSL/hardware/uart_vcd/)

A custom hardware driver that reads 32-bit GPIO state over a USB UART serial port, mapping each bit to a logic analyzer channel (D0-D31). Key design constraints an agent must honor:

- **Device type must be `DEV_TYPE_USB`** (not `DEV_TYPE_SERIAL`). DSView's `is_hardware()` only checks `DEV_TYPE_USB`, so using `DEV_TYPE_SERIAL` disables Loop mode, stream mode, and other hardware features.
- **`SR_DF_END` must be sent by `receive_data` callback**, not by `hw_dev_acquisition_stop`. Sending END from stop causes a double-END crash because the session loop calls stop twice.
- **Serial fd uses `VMIN=0, VTIME=1`** (blocking up to 100ms). Do not use `O_NONBLOCK` — it causes polling spin and GUI hangs on stop.
- **Device dedup via `drvc->instances`** in `hw_scan` to avoid duplicate entries on re-scan.
- The driver supports two protocols: `RAW` (fixed 4-byte-per-sample, 32-bit LE) and `EVENT` (varint delta-time + toggle-mask, ~141x compression). Protocol is selected by `UART_VCD_DEFAULT_PROTOCOL` in `uart_vcd.h`.
- **Data path**: serial bytes → `pack_output_block` (64-sample/256-byte → `SR_DF_LOGIC` LA_CROSS_DATA) → `data_feed_callback` in `sigsession.cpp` → `LogicSnapshot::append_cross_payload` → UI rendering.
- Detailed design docs: `uart_vcd_session_memory.md`, `uart_vcd_data_path.md`, `test_uart_vcd_event_protocol.md`.

## Compile commands / IDE

The `cmake-build-debug-system-gcc13/` directory contains a ninja-based build with a working `compile_commands.json`. Symlink or copy it to the repo root for clangd/LSP support.

## Tests

Tests are off by default. Enable with `cmake -DENABLE_TESTS=ON .`. The test binary is at `DSView/test/`.

## Logging

- Log system: `common/log/xlog.c` / `common/log/xlog.h` (xlog).
- Control via `--loglevel 0-5` or `--storelog` CLI flags.
- App config can also enable persistent logging (`AppConfig::appOptions.ableSaveLog`).
